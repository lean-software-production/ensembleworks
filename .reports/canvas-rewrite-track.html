Perf-parity push merged

Two PRs stacked on each other, both authored directly by a human (Trevoke), not subagent-driven like Phases 1–4: main ← #48 fix/v2-boot-sync-ready ← #50 perf/v2-first-shape-harness. #50 merged into #48's branch first; that combined branch then merged into main via #48's own merge, commit 2d46a93, 2026-07-20. Neither PR got a human review before merging — a deviation from every prior phase's review-gate pattern.

PR #48 — real sync-readiness signal

Replaced v2's fixed 400ms boot sleep with an actual signal: a new additive protocol frame Frame.SyncDone (tag 4), sent by the server right after the backfill Update in reply to a SyncRequest. SyncClientPeer.ready() resolves on it (re-armed on every reconnect()). CanvasV2App.boot() now races peer.ready() against a 400ms safety-cap delay instead of always sleeping the full 400ms. Deploy-safe since unknown frame tags were already ignored by both peers.

PR #50 — load-parity measurement (does not fix)

A time-to-first-shape harness seeding a room over the real /sync/v2 WebSocket, against a production vite build served by vite preview.

Headline finding: v2@100 shapes loaded at 1.18x v1@100's time-to-first-shape (506.8ms vs 428.7ms), against the owner's acceptance bar of ≤1.00x. Measured, not fixed by this PR.

Candidate causeVerdict
Oplog volumeRuled out — 1.00x
Toolbar → first-shape gapRuled out — ~0ms
Cold-actor replayNot implicated — 28.7ms delta
Client-side bootstrapImplicated — ~300ms (~55–60% of load); tied to v2's ~4.2MB lazy CanvasV2App chunk vs v1's ~1.7MB tldraw chunk

Comparability caveats stated in the PR itself: the measured engine-only delta is ~78ms, not ~300ms (v1's own bootstrap was never sub-split); v2's seed content is simpler, which biases 1.18x to understate the real gap; different DOM selectors (.tl-shape vs [data-shape-id]) whose equivalence is unverified; different seeding transports; and 100-shape/loopback-only scale hides real bandwidth cost.

Also added: a double-gated (EW_CANVAS_SYNC=1 AND EW_CANVAS_TEST_EVICT=1) test-only cold-actor eviction route, POST /api/canvas-v2/test/evict/:roomId, in server/src/app.ts — inert unless both flags are set, and a live socket still vetoes eviction.

Runbook: never set EW_CANVAS_TEST_EVICT=1 on staging or prod outside a deliberate, supervised perf run — it's a live, unauthenticated HTTP control-plane surface once both flags are set.

PR #57 — core authoring parity + write-path safety open, not yet merged

Correction to the "has landed" framing: as of this update, PR #57 is open against main — mergedAt is null and there is no merge commit on main. It is feature-complete, mergeable, and every CI check is green (bundle-size, canvas-v2-load, canvas-v2-perf, e2e, unit-tests all pass), with no reviewer decision recorded yet. Treat the summary below as "what this PR will do once merged," not as already-shipped.

Takes v2 from "renders shapes" to "you can actually author on it." Four things land together (branch fix/v2-write-validation, author Trevoke, 132 files changed, +29,763/‑339):

  • Styling, copy/paste, and stacking (z-order) — full parity with v1 today, including real cross-app copy/paste (not an in-app buffer) and stacking that actually re-renders.
  • New shape types — freehand drawing, lines, and images (with a proper asset store), the shape types v2 was missing.
  • Multiple pages — create, switch, rename, reorder.
  • A data-loss fix — a malformed shape can no longer cascade-delete everything nested inside it. Proportionate repair now drops only the offending shape and rescues its children onto the page they were already on, rather than wiping the whole subtree.

Delivered as eight reviewed sub-projects (subagent-driven: implementer + two-stage spec/quality review + fix loops per task, same discipline as Phase 4), with full write-path validation added at both the putShape and updateProps boundaries — pasted/dropped content is now treated as untrusted and re-validated (including against Loro's own undefined→null coercion) before it can touch a document. Nine new interaction contracts land in @ensembleworks/interaction-contracts (draw, line, image-drop, style-apply, paste, duplicate, bring-to-front, page-switch, malformed-clipboard-rejected).

All automated tests green: 240 unit + 50 end-to-end.
